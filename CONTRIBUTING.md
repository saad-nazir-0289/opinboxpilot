# Contributing

## Principles

- Keep commits small, focused, and reviewable
- Prefer meaningful repository improvements over cosmetic churn
- Update docs when behavior or setup changes

## Local workflow

1. Create a branch for your change
2. Run `npm test`
3. Run `npm run build` for frontend-impacting changes
4. Open a pull request with a concise summary of the why

## Commit style

- `Feat:` for user-facing functionality
- `Fix:` for bug fixes
- `Docs:` for documentation updates
- `Test:` for automated tests
- `Chore:` for non-user-facing maintenance

## Safety

- Never commit real secrets or `.env`
- Sanitize logs and screenshots before sharing them publicly
